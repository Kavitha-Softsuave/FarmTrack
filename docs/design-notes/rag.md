## Status of pgvector
- **PgVectorStore has NOT been run against a real PostgreSQL.** Docker Desktop is installed but the daemon was not running (`docker ps` fails on the named pipe), there is no local PostgreSQL, and no pip-installable embedded Postgres with pgvector exists for Windows/Python 3.13 (`pgserver` has no wheel here). I did not start Docker Desktop myself.
- What is covered instead: `tests/rag/test_store.py` runs the same store contract tests against `InMemoryVectorStore` always and against `PgVectorStore` when `PG_TEST_URL` is set (needs `pip install "psycopg[binary]"` and a throwaway DB; the fixture drops/creates `kb_notes`). Without a database, a recording fake engine checks the SQL that is generated (DDL columns, `ON CONFLICT (note_id) DO UPDATE`, `<=>`, bound crop parameters, schema created once).
- To run it for real: `docker run -d -p 5433:5432 -e POSTGRES_PASSWORD=pw -e POSTGRES_DB=kbtest pgvector/pgvector:pg16`, then `PG_TEST_URL=postgresql+psycopg://postgres:pw@localhost:5433/kbtest .venv/Scripts/python -m pytest tests/rag/test_store.py -q`. **Do this once before relying on pgvector.**
- Decision: vectors are sent as text literals cast to `vector` (`CAST(:embedding AS vector)`), so the Python `pgvector` package is not needed at all (the brief said import it lazily; it is never imported). `CREATE EXTENSION` is only attempted if the extension is missing. No ANN index (exact scan; 186 rows). Changing embedding dimension (hash 512 -> OpenAI 1536) needs `DROP TABLE kb_notes`; ingestion skips notes whose text is unchanged, so it does not re-embed after an embedder change either.
- `vector_store=pgvector` with a non-PostgreSQL `database_url` falls back to the in-memory store with a warning.

## Retrieval design (kb.py)
- Notes are indexed from the store (single source of truth). Ingestion runs on first use of the knowledge base (lazy, thread-safe), so `build_container` stays fast. Idempotent upsert: only new or changed notes are embedded; returns the number written.
- **Hybrid score in [0, 1]** = 0.4 x cosine + 0.6 x keyword score. Keyword score = idf-weighted share of query terms found in the note (BM25-style saturation with length normalisation, so a short rule beats a long product note that merely contains the words), with equivalent-term groups (medicine/fungicide/treatment, rain/barish/बारिश, scab/स्कैब, crop names EN<->HI ...). A query term unknown to the notes weighs the most, so off-topic words pull the score down. Cosines below 0.15 count as 0 (hash collisions otherwise return junk for gibberish queries). If the embedder fails the search degrades to keywords only (logged, never raises).
- `search` filters only EXCLUDE conflicts: another crop, another disease, another specific stage. Crop-less, disease-less and stage 'any' notes stay eligible. Scores are returned in `Note.score`.
- `notes_for` order: (1) product notes for the given product ids, in order; (2) rules specific to those active ingredients (dodine rule only if dodine is recommended; captan+oil rule only for captan); (3) notes for crop+disease+stage; (4) crop+disease (disease_info first, then by relevance); (5) general rules by priority safety, waiting period, rotation, rain, mixing, brands, policy, with `min(2, k // 3)` slots always reserved (k=6 gives safe-use and waiting-period rules); (6) semantic fill above 0.12. De-duplicated, stable (ties by note_id).
- **Decision: `product_use` notes are returned by `notes_for` only for the product ids the rules engine chose**, never as "similar products", and never when `product_ids` is empty (expert queue, no approved data). Reason: rules decide what may be recommended; a note about a product the rotation/FRAC rules excluded must not reach the composer. Caller should pass `k >= len(product_ids) + 4`; with more products than `k - 2` the surplus product notes are cut.
- A note whose crop differs from the requested crop is never returned (also not when an apple product id is passed for tomato). Unknown crop (e.g. Mango): only crop-less general notes. `disease_id=None`: no disease-tied notes.
- **Internal notes are stored but never returned** (by `search`, `notes_for`, Ask): tags `grounding` (N136), `photo` (N132), `gap` (N129: carries the US poison-control number, must never be shown), `lowprior` (N133). 186 notes are ingested, 182 are retrievable.
- Data observations: disease catalogue ids are all covered by disease_info notes (N137-N186), so ingestion does not synthesise notes from `disease_catalogue.csv` (a test pins this). 30 notes have no Hindi text yet (Ask then gives the LLM the English text only). N114 (late blight weather rule for potato AND tomato) is tagged crop Potato, and N119-N121 (off-label, banned, proposed-ban policy) are tagged Apple although general: a crop-less tag would be better (data fix, not mine).

## HashEmbedder
Unigrams (weight 1.0), bigrams (0.7), padded character 3-grams (0.3), sub-linear tf, signed hashing (blake2b, dim 512), L2-normalised, stop-words removed, light English stemmer. Hindi: NFKC, nukta dropped, chandrabindu -> anusvara, Devanagari digits -> ASCII, ZWJ removed; tokeniser keeps combining vowel signs (`\w` would split Devanagari words). Purely lexical: no synonyms, no EN<->HI semantics (the notes carry both languages in one embedded text, so an English or a Hindi query each matches its own half). OpenAIEmbedder is tested only with `httpx.MockTransport` (batching 64, retries 429/5xx/transport with 0.5/1/2 s back-off, empty texts skipped, malformed responses rejected, no text in logs or errors); **never run against the real API**. Dimension comes from a table (3-small/ada 1536, 3-large 3072; unknown model assumes 1536 and fails loudly on mismatch).

## AskService (ask.py)
Flow: clean question (control chars, 500 chars) -> crop (named in the question wins, else `crop_id`; two crops named -> clarification) -> refuse crop with no approved product notes when the question is about medicine/spray/dose (`MEDICINE_WORDS`) -> refuse "which medicine/dose?" questions that name no disease, pest or product (that advice comes from a scan) -> retrieve (crop-consistent; product notes and disease-specific notes that name products only if the question names that disease or one of its products) -> best score < `MIN_SCORE` refuses -> LLM -> validate -> citations (`note_id`, `source_ref`).
- **MIN_SCORE = 0.25**, calibrated with the hash embedder on 23 answerable and 22 unrelated questions (EN+HI, `tests/rag/test_ask.py`): answerable questions score 0.29-0.74 (median 0.68), unrelated ones that reach retrieval score at most 0.21 (rice, cricket, bank loan, weather, roses, dragon fruit ...), so 0.25 sits in the gap with about 0.04 on each side. **The gap is narrow and tied to the hash embedder**; with OpenAI embeddings cosines are higher and the threshold must be re-calibrated (run the two lists in the tests and print scores). Score is only the first filter: borderline off-topic questions (e.g. "how much water does tomato need" scores 0.60 via 'water-soaked') still go to the LLM, whose rule is "answer exactly 'I do not know.' otherwise" and whose answer is validated.
- Context = up to 4 notes scoring at least 60% of the best. If no crop is known and notes of two crops compete, answer only if a crop-less general note is the best match; otherwise return a clarification ("tell me which crop"; `refused=True`) when the best score is >= 0.5, or a plain refusal when weaker. The route normally passes `crop_id`, so this is rare.
- Validation (all against the CITED notes only; any failure = polite refusal in the question language): JSON shape; `used_note_ids` non-empty and a subset of the notes shown; answer language by script (Hindi >= 40% Devanagari, English <= 10%); no links; not an "I do not know" in disguise; every number (ASCII or Devanagari digits) appears in the cited notes; no spelled-out dose ("half a litre"; English only); every known product name (active ingredients and brands from the notes, Hindi ingredient names from `hindi_glossary.json`; brands that are ordinary English words such as Score or Stop are skipped) appears in the cited notes; unknown Latin-script names (any in a Hindi answer, capitalised mid-sentence in English) must appear in the cited notes; each sentence must share >= 40% of its content words with the cited notes (catches "the sky is green" and invented lower-case products). Answer is trimmed to 4 whole sentences and 500 chars.
- Known limits: the checks are lexical, not entailment (a wrong paraphrase that reuses note words passes); Hindi spelled-out numbers are not checked (the prompt demands digits); a Hindi product name spelled differently from the glossary is not recognised; a generic question about a crop gets product notes of that crop (prompt rule: say which product each value belongs to).
- Refusal text = N136 wording (EN "I do not have approved advice for this. Please talk to an expert."; HI draft). Hindi is draft for native review.
- No farmer text is logged; only refusal reason codes.
